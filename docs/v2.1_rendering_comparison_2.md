# Audit & Critical Comparison Report: Rendered Artifacts Analysis

This C-Mode Audit provides a critical engineering comparison of the rendered HTML artifacts (`rendered_v1.html`, `rendered_v2.html`, and `rendered_v2.1.html`) evaluated against the source Markdown specification (`source_document.md`).

---

## Executive Summary

| Severity Level | Finding Count |
| :--- | :---: |
| **Critical** | 0 |
| **High** | 2 |
| **Medium** | 3 |
| **Low** | 2 |
| **Informational** | 2 |
| **Total Findings** | **9** |

`rendered_v2.1.html` and `rendered_v2.html` represent significant production-grade architectural overhauls compared to `rendered_v1.html`. They introduce accessible Lucide SVG icons, interactive code-block copy functionality, a Back-to-Top scroll handler, a responsive mobile TOC drawer with focus trapping, and an accurate CJK/Latin hybrid reading time algorithm. 

However, a dataset discrepancy exists between `v2` and `v2.1`: `v2.1` renders a 202-skill dataset (`tf`), whereas `v2` renders the 198-skill dataset (`$d`) matching `source_document.md`.

## Findings & Comparison Breakdown

### 1. High Severity Findings

#### [FINDING-01] Intersecting Heading Tracking Flaw in Table of Contents (`v1` vs `v2`/`v2.1`)
- **Location:** `rendered_v1.html` (Observer callback inside `Td`) vs `rendered_v2.1.html` / `rendered_v2.html` (`ef` & `IntersectionObserver` in `nf`/`ef`).
- **Description:** In `rendered_v1.html`, the `IntersectionObserver` iterates through the entry list and unconditionally sets `activeSlug` to whatever `target.id` happens to be `isIntersecting` during that pass.
- **Evidence:**
  ```javascript
  // rendered_v1.html - Flawed active tracking
  let t = new IntersectionObserver(e => {
    for (let t of e) t.isIntersecting && o(t.target.id);
  }, { rootMargin: `-80px 0px -80% 0px` });
  ```
  In contrast, `v2` and `v2.1` maintain a persistent state Map (`t`) via the helper `ef()` to evaluate all currently visible section headings in viewport order:
  ```javascript
  // rendered_v2.1.html - Robust Map-backed tracking
  function ef(e, t) {
    for (let n of t) e.set(n.target.id, n.isIntersecting);
    for (let [t, n] of e) if (n) return t;
    return ``;
  }
  ```
- **Impact:** `v1` produces erratic TOC active state highlights while scrolling backwards or sweeping across multiple headings. `v2`/`v2.1` maintain accurate, top-down heading highlight state.
- **Severity:** High
- **Recommended Fix:** Adopt the `v2.1` `Map`-backed `IntersectionObserver` pattern across all renders.
- **Confidence:** Verified

---

#### [FINDING-02] Absence of Mobile Drawer Navigation in `v1`
- **Location:** `rendered_v1.html` (`md` layout component) vs `rendered_v2.1.html` (`Nd` & `Pd` components).
- **Description:** `rendered_v1.html` hides the Table of Contents on viewports below `1024px` (`lg:block`) without providing an alternative mobile navigation control.
- **Evidence:**
  - `rendered_v1.html`: Sidebar is `<aside className="hidden w-60 shrink-0 lg:block">` with no hamburger menu trigger or overlay modal.
  - `rendered_v2.1.html`: Implements `Nd` modal drawer triggered by a menu button on mobile viewports (`lg:hidden`).
- **Impact:** Mobile users cannot access document navigation or jump to specific skill categories in `v1`.
- **Severity:** High
- **Recommended Fix:** Retain the `Nd` slide-over modal drawer from `v2.1`.
- **Confidence:** Verified

### 2. Medium Severity Findings

#### [FINDING-03] Reading Time Calculation Inaccuracy for Mixed CJK/Latin Content
- **Location:** `rendered_v1.html` (`Qd` function) vs `rendered_v2.1.html` / `rendered_v2.html` (`$d` function).
- **Description:** `v1` adds word count and CJK character count together, dividing the total sum by `200` words per minute. `v2` and `v2.1` independently compute Latin word reading time (at 200 WPM) and CJK character reading time (at 300 CPM).
- **Evidence:**
  ```javascript
  // rendered_v1.html (Flawed addition)
  let a = r + (i ? i.length : 0);
  return a === 0 ? "0 min read" : `${Math.max(1, Math.ceil(a / 200))} min read`;

  // rendered_v2.1.html (Standard multi-script speed)
  let o = Math.ceil(r / 200),
      s = Math.ceil(a / 300);
  return `${Math.max(1, o, s)} min read`;
  ```
- **Impact:** `v1` inflates estimated reading time on documents containing mixed CJK characters and English technical terms.
- **Severity:** Medium
- **Recommended Fix:** Use the independent script speed calculation from `v2.1`.
- **Confidence:** Verified

---

#### [FINDING-04] Absence of Code Snippet Clipboard Copy Affordance in `v1`
- **Location:** `rendered_v1.html` (`pre` renderer) vs `rendered_v2.1.html` / `rendered_v2.html` (`Vd` & `gd` components).
- **Description:** Code blocks in `v1` are static `<pre>` tags. `v2` and `v2.1` wrap `<pre>` elements in `Vd` with an embedded `gd` copy button, utilizing `navigator.clipboard.writeText` with an unstyled `textarea` fallback and temporary confirmation state.
- **Evidence:**
  - `v1`: `pre: ({children}) => <pre className="...">...`
  - `v2.1`: `pre: ({children}) => <Vd>{children}</Vd>`, which includes `gd` with `aria-label={n ? 'Copied!' : 'Copy code'}` and `aria-live="polite"`.
- **Impact:** Decreased usability for users attempting to extract code or skill definitions.
- **Severity:** Medium
- **Recommended Fix:** Retain the `Vd`/`gd` copy block component from `v2.1`.
- **Confidence:** Verified

---

#### [FINDING-05] Modal Accessibility & Focus Management Deficiencies in `v1`
- **Location:** Overall DOM Structure & Dialog Controls.
- **Description:** `v1` lacks dialog primitives, focus traps, body scroll locking, and `Escape` key bindings. `v2.1` implements comprehensive accessible dialog ergonomics in `Nd`.
- **Evidence:**
  - `v2.1` `Nd` component includes:
    - `role="dialog"`, `aria-modal="true"`, `aria-label="Table of contents"`
    - Keyboard handler for `Escape` (`e.key === 'Escape' && r(!1)`)
    - Focus management (`a.current?.focus()`)
    - Body scroll-lock cleanup (`document.body.style.overflow = 'hidden'`)
- **Impact:** Non-compliance with WCAG 2.2 AA standards for keyboard and screen-reader users in `v1`.
- **Severity:** Medium
- **Recommended Fix:** Use `v2.1` modal patterns.
- **Confidence:** Verified

### 3. Low Severity Findings

#### [FINDING-06] Theme Toggle Visual Representation (`v1` Emojis vs `v2.1` SVG Icons)
- **Location:** `rendered_v1.html` (`cd` component) vs `rendered_v2.1.html` (`Md` component).
- **Description:** `v1` renders raw text emojis (`☀️`, `🌙`, `💻`) inside the theme toggle button. `v2.1` renders Lucide SVG icons (`Sun`, `Moon`, `Monitor`).
- **Evidence:**
  - `v1`: `children: e === 'light' ? '☀️' : e === 'dark' ? '🌙' : '💻'`
  - `v2.1`: Uses SVG components (`md`, `pd`, `fd`) with explicit `aria-hidden="true"`.
- **Impact:** Emojis render inconsistently across OS/browser environments and disrupt visual alignment.
- **Severity:** Low
- **Recommended Fix:** Retain Lucide SVG icons.
- **Confidence:** Verified

---

#### [FINDING-07] Lack of Screen Reader Announcements for Dynamic Theme Changes in `v1`
- **Location:** `rendered_v1.html` (`cd` component).
- **Description:** `v1` updates `document.documentElement` attributes silently. `v2.1` incorporates an `aria-live="polite"` live region that announces theme updates to assistive technology.
- **Evidence:** `rendered_v2.1.html` contains `<span aria-live="polite" className="sr-only">{n}</span>`.
- **Impact:** Screen-reader users receive no feedback when toggling light/dark/system themes.
- **Severity:** Low
- **Recommended Fix:** Retain the live region notification pattern from `v2.1`.
- **Confidence:** Verified

---

### 4. Informational Findings

#### [FINDING-08] Dataset Versioning Mismatch Between `v2.1` and `v2`/`source_document.md`
- **Location:** `rendered_v2.1.html` vs `rendered_v2.html` (`tf` vs `$d` constants).
- **Description:** `rendered_v2.1.html` renders the `tf` dataset (containing 202 skills), whereas `rendered_v2.html` renders the `$d` dataset (containing 198 skills, matching `source_document.md`).
- **Evidence:**
  - `rendered_v2.1.html`: `const {frontmatter, body} = useMemo(() => Xd(tf), []);` -> Header: `202 skills`.
  - `rendered_v2.html`: `const {frontmatter, body} = useMemo(() => Xd($d), []);` -> Header: `198 skills`.
- **Impact:** Deployment of `v2.1` displays an expanded catalog compared to the raw `source_document.md` file attached.
- **Severity:** Informational
- **Recommended Fix:** Ensure the desired dataset (`tf` 202 skills vs `$d` 198 skills) is explicitly configured based on target production release requirements.
- **Confidence:** Verified

---

#### [FINDING-09] Unused Stale Markdown Constant in `rendered_v2.1.html` and `rendered_v2.html`
- **Location:** Both `rendered_v2.1.html` and `rendered_v2.html` bundle files.
- **Description:** Both files bundle both markdown strings (`tf` and `$d`), but each file only renders one of them.
- **Evidence:** `rendered_v2.1.html` uses `tf` and leaves `$d` unread; `rendered_v2.html` uses `$d` and leaves `tf` unread.
- **Impact:** Unnecessary bundle bloat (~110 KB of duplicated string literals in the production HTML bundle).
- **Severity:** Informational
- **Recommended Fix:** Dead-code eliminate the unused string variable before final bundling.
- **Confidence:** Verified

## Conclusion & Recommendation

`rendered_v2.1.html` represents the superior UI/UX and architectural implementation, resolving every functional defect identified in `v1`. 

If your intention is to match the exact 198 skills in `source_document.md`, deploy **`rendered_v2.html`** (or point `rendered_v2.1.html`'s `Xd()` call to `$d`). If the target release includes the 4 newly added skills (202 total), deploy **`rendered_v2.1.html`** as-is.
